# Исправление AppArmor для Discord на Linux (Ubuntu 22.04 / AppArmor 3.0)

Read in [English](README.md) language

Discord перешел на новую модель обновлений: теперь в крохотном `.deb` пакете лежит только программа-загрузчик `updater_bootstrap` и несколько bash скриптов, а само приложение Discord скачивается в домашнюю папку.  
Вместе с этим они добавили профиль AppArmor, который всё ломает.

### В чем проблема
Новый профиль содержит строку `abi <abi/4.0>`, которую понимают только свежие дистрибутивы (вроде *Ubuntu 24.04).  
На **Ubuntu 22.04** парсер AppArmor версии 3.0 "наглухо выходит из чата", из-за чего **весь сервис AppArmor не может запуститься**. 

### Симптомы
- При обновлении или загрузке сервис AppArmor падает с ошибкой (`status=1/FAILURE`).
- В логах: `Could not open 'abi/4.0': Net takogo fajla ili kataloga`.
- Безопасность системы под угрозой, так как профили для других программ (браузеров и т.д.) тоже не загружаются.

### Что сделано
В этом репозитории лежат исправленные конфиги.  
Я заменил ABI на версию `abi <abi/3.0>` (хотя можно вообще эту строку удалить) и убрал ключевое слово `userns`, которое не понимает старый парсер.  
Благодаря флагу `unconfined`, Discord продолжает работать, а AppArmor снова работает.

**Файлы:**
- `discord-ptb` - для версии PTB.
- `discord-canary` - для версии Canary.
- `discord-development` - для версии Development.

### Как исправить
1. Скопируйте нужный файл в `/etc/apparmor.d/` (с заменой).
2. Перезагрузите профили: `sudo systemctl reload apparmor`.

### Быстрое исправление (скрипт)
В репозитории есть скрипт fix.sh, который автоматически применяет исправленные профили AppArmor.  
Использование скрипта:

`sudo ./fix.sh`  
* проверяет версию AppArmor
* автоматически применяет исправление только для поддерживаемых версий (2.13 и 3.0)
* копирует готовые профили в `/etc/apparmor.d/`

### Технические подробности
Под капотом новый `updater_bootstrap` представляет собой бинарный файл, написанный на языке программирования **Rust**.  
Судя по метаданным, он собирался в среде **Nix store**. И хотя использование Nix гарантирует воспроизводимость сборки для самих разработчиков, они явно забыли протестировать итоговые конфиги AppArmor на совместимость со "старыми" LTS-дистрибутивами, что и привело к текущей неразберихе.
